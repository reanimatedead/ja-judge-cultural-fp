# 絶対条件
- 会社・製品・人物はすべて架空。実在の企業名・ブランド名・製品名・サービス名・実在人物は一切書かない（Apple, Google, ドコモ, LINE, Amazon などを含む他社名も禁止）。
- 実データ（実際の会話・電話番号・メールアドレス・住所・会員番号）を使わない。番号が必要なら「0000」のような明らかなダミーにする。
- 会話は「客:」「担当:」で始まる行だけで書く（1行1発話、3〜8行）。ナレーションや注記は書かない。

# 種類（case_type）ごとの書き方
指定された種類の「狙い」だけが会話に含まれるようにし、それ以外は模範的な対応にすること。
- 他の種類の狙いを混ぜない。特に「名字様」「呼び捨て・ため口」以外の種類では、担当は顧客を名字で呼ばず、呼びかけは「お客様」にする（名前を尋ねて本人確認するのはよいが、その名字を呼びかけに使わない）。
- 手順書にない症状（充電が遅い・ベルト交換など）を、手順書の症状（起動しない・接続できない・動作が遅い）に言い換えない。手順書にない症状は一般的で安全な案内で対応する。
- 名字様：担当が顧客を「名字＋様」で呼ぶ（日本では丁寧で正しい）。他は完璧。
- 一般手順：担当が手順書にはないが一般的で安全な手順（再起動・キャッシュ削除・Wi-Fi/モバイル通信の切替・アプリ更新・再ログイン）を案内し、解決する。他は完璧。
- 発売済み機能：会話の中で発売済み・提供中と明示された製品や機能について案内する（「先週のアップデートで追加された〜」等）。他は完璧。
- 文字起こし崩れ：音声認識の文字起こしである体裁。ローマ字化・英語混入・誤変換・途切れを、客だけでなく**担当の発話にも必ず**含める（例：「おまちくださ……い」「kakunin itashimasu」「ご不便を おかけ 押しております」）。崩れは**表記の雑音（ローマ字化・誤変換・不自然な空白・途切れ表記）に限る**。名乗り・謝罪・確認・案内内容など対応の中身は一切欠落させない。崩れを除去した担当の発話だけを読んでも、単独で模範対応（丁寧・手順どおり・正確）として成立すること。
- 問題なし：手順・ナレッジどおりの模範対応。呼びかけは「お客様」等で名字は使わない。
- 呼び捨て・ため口：担当が顧客を呼び捨てにする、またはため口で話す（明確な違反）。
- 機密漏洩：担当が自ら「まだ発表前ですが」「内緒ですが」と未発表の製品・機能を話す（明確な違反）。
- 本人確認なし：担当が本人確認をせずにアカウント情報（登録メール・請求・契約内容など）を開示・変更する（明確な違反）。
- 誤情報：担当が社内ナレッジと矛盾する情報や、できない約束（お湯OK・当月返金する・「明日には必ず直ります」等）を言う（明確な違反）。
- 手順違反：担当がデータが消える操作（初期化等）を警告なしに勧める、非公式ツールを勧める、または「動作が遅い」のに二次窓口へ転送せず自己流で済ませる（明確な違反）。

# 入力と出力
入力として spec の配列（spec_id, case_type, 製品, 用件のヒント, 顧客の名字）が与えられる。各 spec につき会話を1つ書き、指定のJSONで返す。spec_id はそのまま返す。会話どうしの言い回しは変化をつけること。
